# 66. 目标矩形验证：1320×2232 满屏，"画到屏幕外"假设排除

日期：2026-10-21

## 实验

用 Commit 日志的两个槽 dump 目标矩形计算的另外两个关键项（docs/65 第 3 条）。

| 图层偏移 | 我们 | 含义 |
|---|---|---|
| `+0x0c` | **1320** | 目标宽乘数 |
| `+0x24` | **1320** | 目标宽除数 |
| `+0x10` | 2232（docs/50） | 目标高乘数 |
| `+0x28` | 2232（docs/61） | 目标高除数 |

代入 paint 的公式：

```
dest_w = obj_w × layer[0x0c] / layer[0x24] = 1320 × 1320 / 1320 = 1320
dest_h = obj_h × layer[0x10] / layer[0x28] = 2232 × 2232 / 2232 = 2232
```

**目标矩形 1320×2232，满屏，正确。**

⇒ docs/65 提的"path A 的 y 偏移把画面画到可视区外"**假设排除** ——
即使偏移为 0，矩形本身也是对的，而且此前强制 path B（无偏移）仍黑。

## 下一步（二选一）

**A. dump 像素内容本身**（最后的"数据"维度）
绘制函数 `fn(x,y,w,h)` 不收纹理参数，纹理在更早处绑定。
但 `gbuffer` 对象的 `+0x30/+0x38` 是 0 —— 也许**真正的像素指针在别的字段**
（`+0x04`/`+0x08`/`+0x10`/`+0x14`/`+0x1c`/`+0x28`/`+0x2c` 尚未查）。
可一次性多 dump 几个（改 Commit 日志偏移即可，一次开机 2 个）。

**B. 直接查 ops 表 `**(0x7b41920)` 的实现**
（`0x796154` 处 `blr x4` 调用的函数）。若它在两边是不同实现，
或它依赖某个初始化状态，就能解释"画出来是黑"。

> 倾向 **B**：A 的字段已经查了 4 个都无信息，而 B 直接指向"画"这个动作本身。
