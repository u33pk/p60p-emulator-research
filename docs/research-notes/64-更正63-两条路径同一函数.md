# 64. 更正 63：两条绘制路径用同一函数；gbuffer+0x00 也是 0

日期：2026-10-21

## 更正

docs/63 说"path A / path B 用不同的 ops 表"是**错的**。重新看反汇编：

```
path A (0x796100):
  x0 = *(0x7b41920);  x4 = [x0]        ← 同一张表、同一个函数
  x0 = *(0x7b487d0);  w0 = [x0]
  w1 = [x29+0x40];    w0 = w1 - w0     ← 只是把 y 减去一个偏移
  w3 = [x29+0x48];  w2 = [x29+0x44]
  w1 = w0;            w0 = [x29+0x4c]
  blr x4                              ; fn(x, y-offset, w, h)

path B (0x796138):
  x0 = *(0x7b41920);  x4 = [x0]        ← 同一张表、同一个函数
  w3 = [x29+0x48];  w2 = [x29+0x44]
  w1 = [x29+0x40];  w0 = [x29+0x4c]
  blr x4                              ; fn(x, y, w, h)
```

**两条都调同一个 `fn(x, y, w, h)`，唯一区别是 path A 多做一个 y 偏移。**
所以 docs/63"强制 path B 仍黑"说明的不是"路径选错"，而是**这个 fn 画出来就是黑**。

分支条件是 `bl 0x110c8c4` 与 `bl 0x11a8058` 两个 bool，都为真才走 path A。

## 现状

绘制函数 `fn(x,y,w,h)` 被正确调用、参数正确，但**画出来是黑**。
⇒ **源纹理是空/黑**。

而这个 `fn` 不直接收纹理参数（只有 x/y/w/h），
说明**纹理是在别处绑定的**（GL 状态），需要找到绑定那一步。

## 下一步

1. **找纹理绑定**：paint 函数里 `blr` 之前没有直接的纹理参数，
   纹理必然在更早处绑定。查 `opengl_paint_composer_layers` 的**调用者**
   （`0x7945ec: bl 0x795df4` 之前）或函数开头的 GL 状态设置
2. **dump `**(0x7b41920)`**（那个 fn 指针），对比 6.0.0 与我们是否同一个实现
3. **查 guest 侧像素上传**：`gbuffer_data_guest_to_host` 加计数，
   确认像素是否真的到了宿主

> 个人倾向 **1**：`fn(x,y,w,h)` 只画不取源，源在哪绑定是关键缺口。
