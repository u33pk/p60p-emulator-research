# 50. 图层线格式字段逐个比对：已比 4 个，全部一致

日期：2026-10-21

## 比对方法

改 Commit 处理里那条日志的取数来源（`0x79457c` / `0x794584` 的 `ldr` 偏移），
把 printf 的 `num %d` / `calc size %lld` 两个参数指向图层结构的不同偏移，
一次开机拿 2 个字段，两边各跑一次对照。

## 已比对结果

| 图层偏移 | 我们 | 6.0.0 | 一致? | 含义 |
|---|---|---|---|---|
| `+0x00` | 0 | 0 | ✓ | 首字段 |
| `+0x10` | 2232 | 2232 | ✓ | 屏幕高度（1320×2232） |
| `+0x14` | 3 | 3 | ✓ | gbuffer 查找参数之一 |
| `+0x1c` | 0 | 0 | ✓ | — |
| `+0x18` | 8（`not support transform_type 8`） | 8（同） | ✓ | transformType |
| `+0x20` | 非空（判空日志计数 0） | 非空 | ✓ | gbuffer 指针 |
| `+0x34` | 0（`gbuffer_id:%d`） | 0 | ✓ | 传给查找函数的 id |

加上 `hidumper` 的语义字段（zOrder / compositionType / blendType / layerAlpha /
layerRect / cropRect / 缓冲状态）逐字段一致，
**图层结构几乎可以确定是完全相同的**。

## 结论

差异不在图层结构。剩余可能只有两个：

1. **gbuffer 像素内容**（宿主拿到的缓冲里是空白/黑屏，而不是锁屏画面）
2. **宿主 paint 之后、present 之前的呈现目标**（画对了但没送到窗口）

## 下一步

### A. 查 gbuffer 像素内容

`opengl_paint_composer_layers` 里双缓冲交换发生在 `gbuffer+0x30` / `gbuffer+0x38`：

```
0x79638c  x0 = layer+0x20            ; gbuffer
0x796390  x0 = [x0 + 0x38]           ; gbuffer->0x38
0x796394  str x0, [x29+0x60]
0x7963a8  x1 = [x1 + 0x30]           ; gbuffer->0x30
0x7963ac  str x1, [x0 + 0x38]        ; 交换
0x7963c8  w0 = 0x9117                ; opcode
0x7963cc  blr x2                     ; ops->fn(0x9117, 0, gbuffer)
```

可以按同样的办法 dump `gbuffer->0x30` / `0x38` 指向的头几个像素字节，
两边对比即可知道像素内容是否一样。

### B. 查呈现目标

`display_present`（`0x796434`）：

```
swap(ctx->0x20, ctx->0x28)
ops->fn(0x8d40, *(ctx->0x20)->0x20)
```

`ctx->0x20` / `ctx->0x28` 两边都非空。可以 dump `*(ctx->0x20)->0x20`
（最终被呈现的目标）以及 opcode `0x8d40` 的 ops 实现，
确认画完之后是不是真的送到了窗口。

## 插桩补丁现状

`sdk/emulator/Emulator` 当前是**字段 dump 版**：
4 处基础插桩（docs/49）+ 2 处取数偏移（`0x79457c` / `0x794584`）。

原版备份 `tmp/Emulator.before_instr`。
做字段 dump 时只需改那 2 处的 `ldr` 偏移：

| 偏移 | 编码形式 | 含义 |
|---|---|---|
| `0x79457c` | `0xb9400004 \| (imm<<10)` | `w4 = [x0, #imm]`，打印为 `num %d`，实际偏移 = imm+4 |
| `0x794584` | `0xb9400000 \| (imm<<10)` | `w0 = [x0, #imm]`，打印为 `60*值+4`，可反解 |

> 实测：`0xb9401804` → 偏移 0x18（=layer+0x14）；`0xb9400400` → 偏移 0x04（=layer+0x00）。
