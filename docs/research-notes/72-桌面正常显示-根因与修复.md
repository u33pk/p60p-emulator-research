## 根因链（三层）

```
guest 没有 QemuParams / 从不发 "boot-complete"
        ↓
宿主 BootCompletePipeClientRecv 收不到 → 不撤开机占位图、不进 live 呈现态
        ↓
整帧读回(glReadPixels+PBO)+swap 从不执行 → 窗口永远是占位图(转圈)/黑
```

**证据**（详见 docs/71）：
1. GL 拦截层（`tmp/glshim.c`）双侧对比：渲染两边都正常（UI 绘制 1282 vs 1477 次），
   但手机 ROM **0 次**整帧读回，对照组每帧一次
2. 时间决定性：对照组首次整帧呈现与 `guest os boot completed.` **同一秒**
3. 手机 ROM 的宿主日志里 boot-complete 一次都没有
4. 官方镜像中唯一含 `boot-complete` + `/dev/express_pipe` 的组件是 `QemuParams`
   （由 init 拉起，但**无任何 init cfg 引用**），我们的镜像里没能正确发信

## 修复：延迟触发 boot-complete（宿主侧，时机正确）

此前直接在二进制里打补丁抢跑 boot-complete 会**破坏正常出屏**（docs/71 第五节）：
消息路由被打乱、过早触发、重复触发都有害。

**最终方案：LD_PRELOAD shim，等 guest 就绪后再触发一次**（`tmp/glshim.c`）：

```c
/* BOOTFIX_DELAY 秒后（默认 150s，此时 guest 已起、参数已处理完） */
void *base = find_exe_base();              /* /proc/self/maps 里 Emulator 的加载基址 */
*( *(base + 0x7b2ef60) ) = 1;              /* boot-complete 标志 */
((void(*)())(base + 0x1059a14))();         /* OnBootCompleted（含 StopBootAnimation）*/
void *obj = ((void*(*)())(base + 0x1052268))();
((void(*)(void*,void*))((void***)obj)[4])(obj, *(void**)(base + 0x7b37330));
                                            /* EmitGuestOSBootComplete */
```

只在**主进程**（`primary.pid` 记录的第一个加载 shim 的进程）触发一次，
参数消息照常被 QemuBootParamsAdd 处理，时序与官方一致。

**效果**：占位图消失、整帧读回每帧一次、锁屏出屏、交互可用、时钟走动。

## 复现方法

```sh
cd <WORKSPACE>
export DISPLAY=:0 XAUTHORITY=/run/user/1000/.mutter-Xwaylandauth.<TOKEN>
export GLSHIM_DIR=<WORKSPACE>/tmp/gltrace_bf BOOTFIX_DELAY=150
export LD_PRELOAD=<WORKSPACE>/tmp/glshim.so
setsid nohup <WORKSPACE>/sdk/emulator/Emulator -start HarmonyOS_P60P_v2 \
  -instancePath <WORKSPACE>/tmp/deployed_p60pv2 \
  -imageRoot <WORKSPACE>/tmp/image_root_p60pv2 > tmp/emu.log 2>&1 &
# 约 150 秒后 boot-fix 自动触发，锁屏出屏
python3 tmp/xshot.py        # 抓宿主窗口
hdc tconn 127.0.0.1:5555 && hdc -t 127.0.0.1:5555 shell "uinput -T -m 660 1900 660 800"  # 交互
```

## 遗留（不影响「界面正常」，可后续处理）

1. **guest 侧 `snapshot_display` 全黑**：capture 路径与呈现路径的缓冲不一致
2. **锁屏时钟静止时不刷新**：无交互时时钟不走（每分钟的 Commit 不触发 UI 重绘）；
   交互后立即刷新到当前时间
3. **正规化**：目前靠 shim 延迟触发。更正统的做法是让 guest 在合适时机
   发 `boot-complete`（查清官方 `QemuParams` 的启动方式，或写最小 guest 助手
   往 `/dev/express_pipe` 的 `boot-params` 管道写 `boot-complete`）
