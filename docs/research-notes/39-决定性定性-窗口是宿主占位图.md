# 39. 决定性定性：窗口里那张图确认是宿主占位图

日期：2026-10-20
状态：长期悬而未决的"窗口里到底是 guest 画面还是宿主占位图"**已定性**。承接 docs/29~38。

---

## 1. 决定性证据

guest 侧（当前实例，GL 修复已固化进镜像后的新鲜启动）：

```
$ hdc shell 'param get | grep -i bootanim'
ohos.boot.time.bootanimation.started  = 14800356
ohos.boot.time.bootanimation.finished = 14807608     ← 开机动画已结束
ohos.boot.time.bootanimation.ready    = 19882959
startup.service.ctl.bootanimation.pid = 1006

$ hdc shell 'ps -ef' | grep -iE 'bootanim|boot_anim|animation'
（无输出 —— 开机动画进程已退出）

$ hdc shell 'ps -ef' | grep -iE 'sceneboard'
20020020  1730  ... com.ohos.sceneboard
20020020  3639  ... com.ohos.sceneboard:EngineServiceAbility:1
```

⇒ **guest 的开机动画早已结束，桌面（sceneboard）正在运行**，
但模拟器窗口里仍然是「HarmonyOS + 转圈」。

**结论：窗口里那张图是宿主侧的占位图，不是 guest 的开机动画，也不是 guest 桌面。**

## 2. 顺带排除

### 2.1 child window 不是真 X 窗口

```
0xe00006 "Emulator"  585x830+667+184   ← 唯一显示的主窗口，0 个子窗口
0xe00008 "Emulator"  1x1+0+0  Map State: IsUnMapped   ← 未映射的 1x1 辅助窗口
```

主窗口 `xwininfo -children` 显示 **0 children**。
宿主日志里的 `MAIN_CREATE_CHILD_WINDOW` 是模拟器内部的 GL 子表面（Qt/GLFW），
不是 X11 子窗口。所以"子窗口尺寸错了/没贴上去"这个方向不成立。

### 2.2 paint 每次提交都会跑到底

`opengl_paint_composer_layers` 在 `0x795ea8..0x796210`（transform 检查之前）
**没有任何跳到返回点的分支**：

```
branches to RET (0x796414) in 0x795ea8..0x796210 :  （空）
calls in that range: 0x110c88c 0x110c8e0 0x11a8058 0x8440bc 0x7a2bd4 0x110c8c4 0x11a8058 0x7ba304
```

⇒ 之前"`not support transform_type 8` 只出现一次"是因为 transform 后来变成合法值（0/5），
不是 paint 没跑。**paint 确实每帧都在执行。**

### 2.3 Commit 的 size 校验通过

`0x794538..0x794560`：`size == layerCount*60 + 4` 才走 paint 分支；
不等则打 `CommitComposeLayer err! layer_num ... layers_size ...`（行 218）。
该消息**从未出现** ⇒ 每次提交的尺寸都正确，走的都是 paint 分支。

## 3. 当前完整结论

| 环节 | 状态 |
|---|---|
| guest GPU context | `Mali-G77` / `OpenGL ES 3.0 (4.6.0 NVIDIA 595.71.05)`（已固化进镜像） |
| guest 开机动画 | **已结束** |
| guest 桌面 | sceneboard + EngineServiceAbility 运行中，渲染树含真实像素 |
| guest 提交链 | `init → PushFirstFrame → ShowWindow → CommitComposeLayer` 全通 |
| 宿主 `opengl_paint_composer_layers` | **每帧都在跑**，层指针/transform 合法 |
| 宿主 `display_present` | gbuffer 检查通过 |
| **窗口** | **宿主占位图**（本节第 1 条已定性） |

⇒ **缺口 100% 在宿主把 paint 结果呈现到窗口这一段。**

## 4. 下一步

宿主 `sdk/emulator/Emulator` 里剩下的两处：

1. **`display_present` 的 `blr x2(0x8d40, …)`**
   `0x79651c` 起：`x2 = **(0x7b44578)`（一个被 50+ 处引用的 ops 表），
   `blr x2(0x8d40, id)`。需要确认这个调用拿到的目标（纹理/窗口）是否正确。
2. **占位图何时消失**
   窗口里的「HarmonyOS+转圈」是宿主资源（`Emulator` 二进制里的 Qt resource，
   `HarmonyOS` 字符串 120 处，多为字体名/UI 文案）。
   要找它被移除/覆盖的条件 —— 很可能就是上面那条 present 链的成功回调。
