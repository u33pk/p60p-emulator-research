`+0x00`=0、`+0x20`=2、`+0x30`=0、`+0x38`=0（其中 +0x20/+0x30/+0x38 与 6.0.0 一致）。

## 更正/补充 docs/64

docs/64 已更正 63（两条路径同一 ops 表）。本轮补一句：
**`0x7960ec` 的分支条件是 `bl 0x110c8c4` 与 `bl 0x11a8058` 两个 bool**，
都为真才走 path A（带 y 偏移），否则 path B。
强制 path B 在我们这边仍黑，说明**这个 fn 画出来就是黑**。

## paint 函数的直接调用全图（本轮新扫）

循环体（`0x795f54` – `0x796160`）内只有 4 个直接 `bl`：

```
0x795fac  bl 0x8440bc      ; 参数设置器（校验 w0 在 [0, 0x3fff]）
0x795fb4  bl 0x7a2bd4      ; gbuffer 对象查找（返回 obj，obj+0x78/0x7c 为宽高）
0x7960e0  bl 0x110c8c4     ; bool，决定 path A/B
0x7960f0  bl 0x11a8058     ; bool，决定 path A/B
```

**循环体内没有纹理绑定调用。** paint 序言（`0x795df4`–`0x795f20`）也只是
表基址计算，没有 GL 调用。

⇒ 纹理绑定不在 paint 函数内，**在调用者或更早处**。
