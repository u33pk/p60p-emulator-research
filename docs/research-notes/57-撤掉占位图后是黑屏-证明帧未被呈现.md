# 57. 撤掉占位图后是黑屏 —— 证明 guest 帧确实没被呈现

日期：2026-10-21

## 实验

把 `Emulator` 里创建 logo 控件的 `QWidget::setParent` 调用 NOP 掉
（`0x11065a8`，函数 `0x110652c` 负责创建 `QSvgWidget(":/common/harmonyos_logo")`
并挂到父窗口），使开机占位图的 logo 不显示。

## 结果

| | 窗口屏幕区 |
|---|---|
| 正常 | 42KB 占位图（HarmonyOS + 转圈） |
| **NOP setParent 后** | **34KB 黑屏** |
| 参考：禁用 present | 34KB 黑屏 |
| 参考：6.0.0 正常 | 206KB 桌面 |

同时确认 guest 侧完全正常：

```
提交次数 183
图层字段正确（layer+0x08 = 0，60*0+4 = 64）
gbuffer_from_global_map = 0（查找成功）
transform_type 日志正常
```

## 结论（重要更正）

**docs/55 里"guest 帧大概率一直在被呈现，只是被占位图盖住了"是错的。**

撤掉占位图后是**纯黑屏**，不是 guest 的锁屏画面。
说明 **guest 帧根本没有被呈现到窗口** —— 占位图不是遮挡物，
它只是掩盖了"什么都没有"这个事实。

现在的状态是：
- 占位图可以去掉（本轮已验证）
- 但去掉后露出的是**黑屏**
- guest 侧渲染、提交、图层结构全部正常

⇒ 问题仍然是「guest 的合成输出 → 宿主窗口」这一段的最后一环
（paint 画的是黑，或 present 送到了错误的目标）。

## 占位图的构造（顺带查清）

```
0x110652c  创建 QSvgWidget(":/common/harmonyos_logo")，存到 this+0x30
0x11065a8  QWidget::setParent(...)        ← 本轮 NOP 这里
```

`BootAnimationLabel` / `ShowBootAnimation()` / `StopBootAnimation()` 属于
`EmulatorWindowEvent`。撤除触发链见 docs/55
（`boot-complete` 管道消息 → `OnBootCompleted` → `StopBootAnimation`）。
