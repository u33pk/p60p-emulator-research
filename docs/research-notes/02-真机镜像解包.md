# 02 - 真机镜像（p60p_rom）解包

记录使用 `update_packaging_tools` 解包 P60 Pro 真机升级包 `update.bin` 的过程与结果。

## 解包方法

依据 `update_packaging_tools/README_zh.md` 的"补充说明"（中文版独有章节）：

```bash
# python 环境（uv）
cd tmp && uv venv venv && source venv/bin/activate
uv pip install xmltodict cryptography asn1crypto

# 解包（注意：输出目录必须已存在，否则报 FileNotFoundError）
mkdir -p tmp/unpack_out
cd update_packaging_tools
python3 build_update.py <输出目录> <升级包所在目录> -unpack <文件名>

# 本次实际命令
<WORKSPACE>/tmp/venv/bin/python3 build_update.py \
  <WORKSPACE>/tmp/unpack_out <WORKSPACE>/p60p_rom -unpack update.bin
```

参数含义（对照 `build_update.py` 源码）：
- 位置参数 1 `target_package`：解包输出根目录（**须预先创建**，`type_check` 不会代建）
- 位置参数 2 `update_package`：升级包所在目录
- `-unpack`：相对文件名，与位置参数 2 拼接后须为真实文件

解包 8.3GB 用时约 10 秒（稀疏写入），结果目录带时间戳后缀：
`tmp/unpack_out/unpack_result_221524/`

## 解包结果（44 个文件）

主要分区镜像：

| 文件 | 大小 | 说明 |
|------|------|------|
| `system.img` | 3.6G | EROFS（LZ4_0PADDING，4K block） |
| `sys_prod.img` | 2.1G | EROFS |
| `vendor.img` | 820M | EROFS |
| `chip_prod.img` | 750M | 芯片厂商定制分区 |
| `boot.img` | 46M | hisi 签名格式（文件头即 X.509 v3 证书，"Certificate, Version=3"） |
| `ramdisk.img` | 4.0M | data（非 gzip，疑似带 hisi 签名头） |
| `dtbo.img` | 14M | 设备树 overlay |
| `updater_boot.img` | 54M | 升级模式专用（+bak） |
| `modem_fw.img` | 118M | 基带固件 |
| `xloader/bl2/teeos/trustfirmware` 等 | 小 | BL 链与 TEE 固件 |

观察：
- 文件系统为 **EROFS**（模拟器镜像是 ext4/EROFS 待确认，格式本身 QEMU 只负责块设备，内核支持即可挂载）
- `boot.img`/`ramdisk.img` 带 hisi 安全签名头，提取其中内核需要按华为签名格式剥离头部
- 真机为麒麟芯片平台，模拟器为 express 虚拟硬件（express_gpu/express_touchscreen 等 virtio 类设备）

## 与模拟器镜像的关键差异（启动难点）

| 项 | 模拟器镜像（phone_all_arm） | 真机镜像（p60p 解包） |
|----|------|------|
| 内核 | 裸 `Image`（ARM64 boot executable） | 封在签名 `boot.img` 内，需剥离提取 |
| ramdisk | gzip cpio | 带签名头的 `ramdisk.img` |
| 硬件驱动 | express 虚拟设备 | 麒麟真实外设 |

初步方案：用**模拟器自己的内核 + 真机的 system/sys_prod/vendor**，组装新 imageRoot 创建第二个实例试启动（qcow2 overlay 不会改动原始镜像）。预期真机 HAL（hisi HDI 驱动）在 express 硬件上无法工作，能走多远需实测。
