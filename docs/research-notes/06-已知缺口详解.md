# 06 - 已知缺口详解与显示栈进展

对真机系统（p60p）三个已知缺口的现场取证、根因分析和修复路径。

## 缺口 1：无显示（显示栈不通）

### 依赖链

```
UI 界面 ← WMS / render_service ← display_composer HDI 服务
  ← composer_host（HDF 驱动宿主进程）
    ← 模拟器 vendor 的 composer 驱动 .so
      ← express 显示设备（模拟器内核自带）
```

### 现状（本次进展）

- **加载层已修复**：devhost 进程原来 exit 127（musl 加载失败）。根因：`libhdf_host.z.so` 在模拟器镜像里位于 `/system/lib64/chipset-sdk-sp/`（模拟器镜像是扁平布局+/system 子目录的双布局），真机 system 里这个库在真机 **vendor** 的 `/lib64/`。把真机 vendor 的 `libhdf_host.z.so` 注入 p60p system 的 `/system/lib64/chipset-sdk-sp/` 后，127 消失
- **剩余问题**：devhost 现在 exit **255**（进程能启动、驱动初始化失败）。根因是版本错配：`hdf_devmgr`/`libhdf_host` 来自真机系统（6.0.0.107），驱动 .so 来自模拟器 vendor（6.1.1），HDF 核心协议版本不一致，驱动 init 无法完成
- hilog 实证：render_service（存活）反复报 `failed to get sa hdf service manager` / `Get:get IServiceManager failed!`——显示合成器拿不到，无画面

### 修复方向

1. 把注入的 libhdf_host 换成**模拟器 6.1 版**（与模拟器驱动同版本，ABI 对齐）——一个文件的事，优先试
2. 不行就深入 HDF 日志定位具体失败的 ioctl/调用
3. 兜底：保持无头。hdc root 已能完成几乎所有分析工作，显示非必需

## 缺口 2：chip_prod / cust / modem 等真机分区未挂载

### 现状

模拟器分区槽位只有 system/vendor/sys_prod/userdata(/cache)，wrapper 不支持加盘。guest 内实证 `/chip_prod`、`/cust` 为空目录。

| 分区 | 内容 | 缺失影响 |
|------|------|---------|
| chip_prod（750M） | 麒麟芯片厂商库：passthrough HAL、TEE ta/、anco_spec、芯片 SDK | 部分 HAL 不可用；疑似导致 `SetOwner invalid uid: audio` 这类 uid 名解析失败（uid 表可能在这） |
| cust（6M） | 运营商/地区定制 | 基本无影响 |
| modem（118M+） | 基带固件 | 模拟器里无意义 |

### 修复方向

利用 root 优势零成本绕过槽位限制：
- **离线**：解包 chip_prod.img → 内容直接塞进 p60p system 镜像的 `/chip_prod/` 目录（真机 rootfs 里它本来就是空挂载点，塞进去即可见）——`fsck.erofs --extract` + debugfs 或 mke2fs 重建
- **在线**：hdc push + bind mount
- 风险：chip_prod 里 hisi 相关的 .so 若被 HDF 扫描加载可能引入新崩溃源，需配合 hdfconfig 或按目录逐个验证

## 缺口 3：sys_prod 是模拟器版

### 现状与根因

真机 sys_prod（2.1G EROFS）已解包但无法直接用。cmdline 有 wrapper 生成的两条**机型绑定挂载**（写死 PHEMU-FD00）：

```
/sys_prod/variant/hw_oem/PHEMU-FD00/etc/param  → /sys_prod/etc/param
/sys_prod/variant/hw_oem/PHEMU-FD00/etc/window → /sys_prod/etc/window
```

真机 sys_prod 的机型目录是 P60P 型号而非 PHEMU-FD00 → bind 源不存在 → init 等待 5s×2 后死亡（Stage0 实证）。当前挂的是模拟器 sys_prod（Pura X View 的参数、字体、主题、产品特性开关）。

### 修复方向

解包真机 sys_prod → 在其内部创建 `variant/hw_oem/PHEMU-FD00/etc/{param,window}`（内容从真机自身 variant 目录或模拟器对应目录复制）→ EROFS→ext4 管线重建替换。管线已验证可行。

## 其他观察

- hdc shell 的 context 是 `kernel`（模拟器 hdcd 的 secon 在真机策略下的归属），uid=0 功能不受影响
- 整机 SELinux 仍 enforcing（仅 sh/hdcd 域 permissive）
- 一阶段那些"真机才有的分区挂载失败/设备节点失败"日志（secure_storage、audio uid 等）均非致命
