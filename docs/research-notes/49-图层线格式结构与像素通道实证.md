# 49. 图层线格式结构摸清；像素通道两边都活着

日期：2026-10-20

## 本轮进展

1. **插桩补丁修好**（docs/48 提到的 double-free），现在是 4 处，稳定可用。
2. **干净 A/B 复核**：`gbuffer_from_global_map is null` 在 6.0.0 与我们两边都是 **0**，

## 一、60 字节图层线格式布局（反汇编实证）

`display_decode_invoke` 的 Commit 路径：

```
buf = g_malloc0(size)
num = *(int*)buf                       ; buf+0
calc = num*60 + 4
if (size != calc) { log; return }
bl 0x795df4                            ; opengl_paint_composer_layers(buf)
bl 0x796434                            ; display_present
```

`opengl_paint_composer_layers` 的图层循环（`0x795f54`）：

```
x2   = buf
x0   = buf + idx*60
x1   = x0 + 4                          ; → 图层结构起点
把 60 字节复制到本地 [x29+0x70 .. 0x70+0x38]
```

从后续代码读到的字段偏移（本地副本 = 图层偏移）：

| 图层偏移 | 本地偏移 | 用途（实证） | 我们的值 | 6.0.0 的值 |
|---|---|---|---|---|
| `+0x00` | `x29+0x70` | 首字段（被当 w1 用，值 8） | 8 | 8 |
| `+0x0c` | `x29+0x7c` | 值 4 | 4 | 4 |
| `+0x18` | `x29+0x88` | `transformType`（`0x7961e8` 读） | 12 | 12 |
| `+0x1c` | `x29+0x8c` | 值 0 | 0 | 0 |
| `+0x20` | — | **gbuffer 指针**（`0x796320` 判空，空则打 `display_write_gbuffer is null`） | 非空 | 非空 |
| `+0x24` | `x29+0x94` | 值 0 | 0 | 0 |
| `+0x28` | `x29+0x98` | 值 27 | 27 | 27 |
| `+0x2c` | `x29+0x9c` | 值 0 | 0 | 0 |
| `+0x34` | `x29+0xa4` | 传给 `bl 0x7a2bd4` 的 id（查找 gbuffer 对象） | 0 | 0 |

> `+0x34` 就是 `gbuffer_from_global_map is null. gbuffer_id:%d` 打印的值，
> **两边都是 0 且查找都成功**，所以它不是问题。

## 二、像素通道在两边都活着

`opengl_paint_composer_layers` 的单层流程：

```
obj = lookup(layer+0x34)               ; bl 0x7a2bd4，返回非空（两边都非空）
if (obj == 0) → log "gbuffer_from_global_map is null"     ← 两边计数 0，即都非空
... 用 obj+0x78 / obj+0x7c 算宽高比 ...
w0 = layer+0x20 的 gbuffer
if (gbuffer == 0) → log "display_write_gbuffer is null"   ← 两边计数 0，即都非空
swap(gbuffer+0x30, gbuffer+0x38)       ; 双缓冲交换
ops->fn(0x9117, 0, gbuffer)            ; 绘制
```

`display_present`（`0x796434`）：

```
if (ctx->0x20 == 0 || ctx->0x28 == 0) → log "display gbuffer is nullptr"  ← 两边 0
swap(ctx->0x20, ctx->0x28)
ops->fn(0x8d40, *(ctx->0x20)->0x20)
```

⇒ **两个"为空"分支在两边都没触发**，gbuffer 对象、双缓冲、present 目标都非空。

## 三、剩余唯一差异面

语义层（`hidumper` 的 zOrder / transformType / compositionType / blendType /
layerAlpha / layerRect / cropRect / 缓冲状态）**逐字段一致**，
线格式长度一致，字段偏移一致，关键判空分支两边都通过。

⇒ 差异只能在：**60 字节里尚未逐字节比对的字段**（`+0x04/+0x08/+0x10/+0x14/+0x30/+0x3c` 等），
或 **gbuffer 像素内容本身**。

## 四、下一步（可直接照做）

1. dump 60 字节逐字节对比：改 Commit 处理里那条日志的取数来源即可，
   不必新加代码 ——
   `0x79457c` 的 `ldr w4,[x0]`（现取 num）改成 `ldr w4,[x0,#4+4k]` 就能打 `layer[k]`；
   `0x7945c4` 的 `mov x6,x5`、`0x7945c8` 的 `mov w5,w4` 也可改成
   `ldr` 从 `[x29+0x88]`（buf）取不同偏移。
   一条日志 3 个参数 → 一次开机能打 3 个字段，20 次开机太慢，
   **建议直接改成循环打印**（或用 3 次开机打关键的 `+0x04/+0x10/+0x30`）。
2. 若60字节全同，则差异在 gbuffer 像素内容 —— 那就要看 guest 侧
   `libcomposer` 的 `HdiLayer::SetLayerBuffer` 有没有真正把句柄交下去。
