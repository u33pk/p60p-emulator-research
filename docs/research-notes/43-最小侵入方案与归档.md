# 43. 最小侵入方案：真机 system 镜像在模拟器上起桌面（可操作）+ 归档

日期：2026-10-20

## 结论

从 P60P 真机 ROM 原版 `system.img` 出发，**只需 33 处改动**（新增 6、修改 27、删除 0），
即可在华为模拟器里把 guest 桌面完整跑起来并正常操作。

判据（实测，双截图确认）：

- `snapshot_display` 抓到的是完整锁屏（时钟 / 日期 / 状态栏 / 壁纸 / 底部卡片），1320x2232
- `uinput` 滑动解锁后画面实时变化（754KB → 580KB），确认**可交互**
- `com.ohos.sceneboard`、`render_service`、`composer_host` 全部常驻

完整改动清单见 `archive/harmony-p60p-on-emulator/DELTA_MANIFEST.txt`（带 md5），
判据截图见 `archive/harmony-p60p-on-emulator/screenshots/`（guest / host 双侧 10 张）。

> **注意**：模拟器自己的窗口仍然只显示开机占位图（HarmonyOS + 转圈），
> guest 帧没有被呈现到宿主窗口。这是**另一个问题**（见「已知未解决」），
> 不影响 guest 桌面本身正常可用。

## 一、原版镜像从哪来

```
p60p_rom/update.bin
  └─ update_packaging_tools/build_update.py -unpack 解包
       └─ tmp/unpack_out/unpack_result_221524/system.img   ← 原版，EROFS 只读，3.8GB
            └─ fsck.erofs --extract 解出可比对的文件树
```

EROFS 是只读的，无法在原地改。做法是把它转成 **ext4**（6.4GB），
然后用 `debugfs -w` 做最小增删改。**原版 EROFS 文件树保留作基准**（`tmp/pristine_out/`），
任何改动都可以逐字节回溯。

## 二、改动清单（6 新增 + 27 修改）

### 2.1 新增（6 项）

| 路径 | 作用 |
|---|---|
| `system/lib64/libdgles.z.so` | GL 调度器，取自 6.0.1 模拟器镜像。模拟器 GPU 透传的入口，必需 |
| `system/lib64/libEGL_impl.so` | 符号链接 → `libdgles.z.so` |
| `system/lib64/libGLESv1_impl.so` | 符号链接 → `libdgles.z.so` |
| `system/lib64/libGLESv2_impl.so` | 符号链接 → `libdgles.z.so` |
| `system/lib64/libGLESv3_impl.so` | 符号链接 → `libdgles.z.so` |
| `system/lib64/libhuks_engine_core_standard.z.so` | HUKS 引擎（6.0.1）。模拟器没有 TEE，用模拟器版本替代 |

**4 个符号链接是关键**。原版手机镜像里这 4 个 `*_impl.so` 是**4 份内容完全相同的独立副本**，
DGLES 把"当前 GL 上下文"存在 emutls（每模块独立）里，导致 `eglMakeCurrent` 写 A 副本的 TLS、
`glGetString` 读 B 副本的 → 永远 NULL → Skia 初始化失败 → 一帧不画。
改成指向同一个 `libdgles.z.so` 后 TLS 统一，GPU 恢复。（详见 docs/29 / docs/38）

### 2.2 图形 / 显示栈（8 项，模拟器适配必需）

| 路径 | 作用 |
|---|---|
| `system/lib64/libEGL.so` | EGL 入口（6.0.1），走 DGLES 透传 |
| `system/lib64/libGLESv3.so` | GLES 入口（6.0.1） |
| `system/lib64/libegl_effect.z.so` | EGL 扩展（6.0.1） |
| `system/lib64/libdisplay_composer_hdi_impl_1.3.z.so` | 显示 HDI 实现（6.0.1），对接 `/dev/express_display` |
| `system/lib64/libdisplay_composer_proxy_1.0.z.so` | 显示 HDI 客户端桩（6.0.1） |
| `system/lib64/libdisplay_composer_proxy_1.1.z.so` | 同上 |
| `system/lib64/libdisplay_composer_proxy_1.2.z.so` | 同上 |
| `system/lib64/libdisplay_composer_proxy_1.3.z.so` | 同上 |

手机的显示 HDI 是接真实显示驱动的，模拟器要接 `express_display` 虚拟设备，
必须换成模拟器版本。注意 `libcomposer.z.so` **保持手机原版不动**（见「踩坑」）。

### 2.3 `librender_service.z.so`：手机原版 + 2 处补丁

| 偏移（文件） | 原版 | 改为 | 作用 |
|---|---|---|---|
| `0x39a2b8` | `bl 0x503740` | `bl RegisterScreenNodeListener`（`0x39cd68`） | 注册屏幕节点监听，否则桌面节点树建不起来 |
| `0x40f518` | `cbnz w5, +0x58` | `b +0x58` | 去掉条件，强制走屏幕建立分支 |

**这两处必须保留**，去掉后 sceneboard 的窗口树不成立。

### 2.4 服务适配（5 项）

| 路径 | 作用 |
|---|---|
| `system/lib64/libhuks_service.z.so` | HUKS 服务（6.0.1） |
| `system/lib64/libdsoftbus_server_plugin.z.so` | softbus（6.0.1） |
| `system/lib64/libdsoftbus_service_ext_frame.z.so` | softbus（6.0.1） |
| `system/lib64/libsoftbus_server.z.so` | softbus（6.0.1） |
| `system/etc/ld-musl-namespace-aarch64.ini` | 库搜索路径前插 `/vendor/lib64/hdf48`（模拟器 HDF 库） |

### 2.5 签名校验绕过（4 项）

`system/bin/bm`、`system/lib64/libbms.z.so`、`system/lib64/libcode_sign_utils.z.so`、
`system/etc/init/local_code_sign.cfg`（`ondemand: true→false`）。
不改这些，HAP 装不上、起不来。

### 2.6 提权 / 可操作（5 项）

| 路径 | 改动 |
|---|---|
| `system/etc/param/ohos.para` | `const.secure=1→0`、`const.debuggable=0→1` |
| `system/etc/param/hdc.para` | `persist.hdc.mode.usb=disable→enable` |
| `system/bin/hdcd` | 换 root 版 |
| `system/etc/init/hdcd.cfg` | root 版服务定义 |
| `system/etc/selinux/config` | `SELINUX=enforcing→permissive` |

另加 `system/etc/selinux/system_common.cil` 策略放开。
SELinux 走 permissive 是为省事；要更干净可以只放行需要的域，但会显著增加工作量。

### 2.7 启动顺序 / 桌面就绪（2 项）

**`system/etc/init/graphic.cfg` 新增 2 个 job（这是"桌面能起来"的核心之一）：**

```json
{ "name": "bootevent.composer_host.ready",
  "cmds": [ "start render_service" ] },
{ "name": "bootevent.wms.fullscreen.ready",
  "cmds": [ "stop bootanimation" ] }
```

- 等 `composer_host` 就绪才起 `render_service`，否则 RS 找不到显示后端
- 等 WMS 全屏就绪才停 `bootanimation`，否则停在开机画面

**`system/etc/app/app_service_fwk_install_list.json`**：把原版里已有但未登记的 4 个
`shared_bundles`（Animatronix / CloudCommon / FlexibleLayout / PhotoBrowser）
补进安装清单 —— 这是 sceneboard 的动画与布局资源包。

**`system/etc/ams_service_config.json`**：`supportSCBCrashReboot: true→false`，
sceneboard 崩溃时不整机重启（调试期很省事，非必需）。

## 三、本次主动做减法：移除 Vulkan（已验证无损）

原版手机镜像**没有 Vulkan ICD**（`/system/etc/vulkan/icd.d/` 不存在），
Vulkan 驱动本应来自 vendor 的 Mali。之前的实验里我们加了：

- `system/lib64/libzvulkan.z.so`（取自 6.0.0 模拟器镜像）
- `system/etc/vulkan/icd.d/express_icd.arm64.json`（指向上面那个库的 ICD 清单）

**这两项是多余侵入**，实测移除后 guest 桌面照常（冷启动 + 滑动验证通过）。
而且它有害：一旦 Vulkan 可用，`render_service` 会走 Vulkan 外部内存互操作路径，
宿主日志出现 `Host: Interop extension not available: VK_KHR_external_memory_win32`
（Linux 上没有 win32 互操作扩展）—— 这条路是死的。

同批还撤掉了一处历史补丁：`librender_service_base.z.so` 里
`VK_OHOS_external_memory → VK_KHR_external_memory` 的字符串替换。
现在该文件**与原版逐字节一致**。这处补丁把一个"模拟器不支持、于是 RS 会走 GL 兜底"的扩展名
改成了"模拟器支持、于是 RS 走 Vulkan 互操作"，等于把好路改成了坏路。

## 四、如何复现

```sh
# 1. 取原版
python3 update_packaging_tools/build_update.py <out> p60p_rom -unpack update.bin
fsck.erofs --extract=pristine_out --no-sbcrc <解包出的>/system.img

# 2. 转 ext4 并扩容
#    EROFS -> ext4 的转换 + 扩容到 6.4GB（做法见 docs/ 早期笔记）

# 3. 用 debugfs -w 应用 DELTA_MANIFEST.txt 里的 33 处改动
#    每个文件改动后务必补元数据：
debugfs -w -R "sif <path> mode 0100644" img
debugfs -w -R "sif <path> uid 0"        img
debugfs -w -R "sif <path> gid 0"        img
debugfs -w -R 'ea_set <path> security.selinux "u:object_r:system_lib_file:s0"' img
#    改完必须删 instancePath 下对应的 *.qcow2，否则覆盖层会盖住基镜像
```

启动 / 验证：

```sh
export DISPLAY=:0 XAUTHORITY=/run/user/1000/.mutter-Xwaylandauth.<TOKEN>
setsid nohup $SDK/emulator/Emulator -start HarmonyOS_P60P_v2 \
  -instancePath .../tmp/deployed_p60pv2 -imageRoot .../tmp/image_root_p60pv2 \
  > emu.log 2>&1 < /dev/null &
# 约 150~180 秒后
export PATH=$PATH:$SDK/sdk/default/openharmony/toolchains
hdc tconn 127.0.0.1:5555
# 双截图判据（防错位判断）
hdc shell "snapshot_display -f /data/local/tmp/g.jpeg -t 1"   # guest 侧
python3 tmp/xshot.py                                            # host 侧
# 可操作性判据
hdc shell "uinput -T -g 660 1800 660 400 600 1200"             # 滑动解锁
```

## 五、踩坑（别再走回头路）

1. **`libcomposer.z.so` 必须用手机原版**。换 6.0.1 的会 `sysrq: Trigger a crash` 内核 panic。
   三方都不一样：手机 239408 / 6.0.1 231936 / 6.0.0 66240。6.0.0 那个是 HDI 1.4，
   手机和 6.0.1 是 1.3，不能混。
2. **`mount -o remount,rw /` 的在线改动不持久**，重启即回滚。必须改基镜像 + 删 qcow2。
3. **`debugfs write` 后必须补 `mode/uid/gid/security.selinux`**，否则 SELinux 拒载。
4. **`begetctl stop_service render_service` 会让整个模拟器退出**；重启 RS 用 `kill $(pidof render_service)`。
5. **`pkill -x Emulator` 后立刻重启**可能触发 `SingleInstanceClient: Waited too long`；
   用 `setsid nohup … < /dev/null &`。
6. `uinput` 坐标是 guest 屏幕空间（1320x2232），不是窗口坐标。
   `-g` 需要 press ≥500ms 且 total−press ≥500ms。
7. `pidof sceneboard` 查不到，进程名是 `com.ohos.sceneboard`。
8. **vendor 必须配套**：手机 system + 6.0.0 vendor → 根本起不到桌面
   （bootanimation 常驻、无 sceneboard）。当前用的是 6.0.1 的 vendor（`p60pv2_vendor.img`）。

## 六、已知未解决

**模拟器窗口不显示 guest 画面**（显示的是宿主的开机占位图）。
guest 侧渲染、合成、提交链全部正常，`snapshot_display` 证明最终帧是完整锁屏。

已排除：

- `display_present` 的早退（其日志 `display gbuffer is nullptr` 从未出现）
- Vulkan 互操作（本次已移除，无改善）
- `host gl 45/46`、`when creating static vaules 500`（`0x500` = `GL_INVALID_ENUM`）——
  在我们自己的日志里 111:46 混着出现，与出不出屏无关，是噪音
- 配置差异（600 正常实例的 `config.ini` 与我们逐字段一致）

仍在嫌疑线上：

- vendor 侧 `libdisplay_composer_vendor.z.so` 被打了 4 处强制补丁
  （`b` 取代 `cbnz`、`nop` 掉 `bl`、`mov` 取代 `add`），位置在
  `HdiLayer::SetLayerBuffer` / `SetLayerCompositionType` / `SetLayerBlendType` 里；
  `hdf_devmgr` 也有 1 处 `bl` 改目标。这两处正是送帧路径。
- 宿主日志里唯一的硬差异：`fill_teleport_express_queue_elem` 的 `find null prt!!!` ×2
  （6.0.0 正常时一次都没有），出现在显示握手的 `device type: 0` 之后。

绕过方案：直接用 `snapshot_display` 把 guest 合成结果投出来 + `uinput` 注入输入，
即可得到可交互的桌面（guest 的 GPU 由宿主 GL 提供，模拟器窗口不能关）。
